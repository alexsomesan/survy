# Spec 0002: HTTPS for the dashboard

Status: implemented on branch `feat/tls-listener` (ticket [12](../tickets/12-tls.md)). Current sources of truth: [architecture](../architecture.md), [operations, "HTTPS"](../operations.md).

## Problem

The dashboard answers on plain HTTP. Browsers mark it "not secure", and the owner's other router services (the VyOS API, the UniFi controller) now present a publicly trusted certificate. The router already has a wildcard certificate for `*.home.somesan.de`, renewed by an ACME client, so the dashboard should use it instead of staying the one service without TLS.

## Decisions

- **survy terminates TLS itself** (the `DASH_TLS_*` variables), rather than sitting behind a VyOS reverse proxy. One component fewer on the router, and no proxy hop that would hide client addresses.
- **Opt-in and additive.** `DASH_TLS_LISTEN` unset leaves behaviour exactly as before. HTTP on port 80 keeps working; there is no redirect.
- **The certificate is two files that change under a running process.** An ACME client renews roughly every 60 days. survy re-reads the files when they change and never needs a restart or a signal. A half-written pair keeps the previous certificate in service.
- **A missing certificate is not fatal.** The deploy script may run after survy starts at boot, so survy starts anyway and fails handshakes until the files appear.
- **Privileged port, unprivileged serving.** Port 443 is bound as root before the privilege drop, like port 80 ([ADR 0005](../adr/0005-in-process-privilege-drop-keeping-net-admin.md)). The key is then read as uid 65534, so whoever installs the files must make them readable by that user ([operations](../operations.md)).
- **No new dependency.** Standard library `crypto/tls` only (the binary stays static, no cgo).

## Out of scope

HTTP to HTTPS redirect, HSTS, client certificates, ACME inside survy, and automatic installation of the certificate files (the owner's deploy script does that).

## Testing

`internal/tlscert` is a small package with its own tests (real TLS handshakes on loopback): serving, renewal without a restart, a half-written pair, files that appear late. This sits beside the HTTP seam of [ADR 0003](../adr/0003-one-test-seam-at-the-http-api.md) because the behaviour is about the transport, which the seam's in-process handler does not cross. The wiring in `cmd/survy` has no fake behind it and is checked by a smoke run (see the ticket's Results).
